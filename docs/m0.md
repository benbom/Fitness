## Definition of Done (v1.0)

- En användare kan gå till appens URL, registrera konto via Supabase Auth (mail + lösenord + MFA), verifiera mail.
- Samma användare kan starta gratis testperiod, koppla ett Stripe-testkort via Checkout, se prenumerationsstatus växla korrekt via webhook.
- Samma användare kan fylla i profil (mål, nivå, utrustning, skador) — data lagras i Supabase med RLS så bara ägaren kan läsa.
- Samma användare kan begära export av sin data och få JSON via mail inom timmar.
- Samma användare kan radera sitt konto — RLS-cascade tar bort all data inom sekunder, verifierbart i Supabase-dashboarden.
- Alla externa credentials i Vercel Environment Variables. Inget hemligt i repo.
- Sentry pingar när något oväntat går fel.
- Deploy från main går grönt utan manuell hand — Vercel bygger och släpper preview per PR + produktion på main.
- Runbooks för deploy, rollback och Supabase-radering ligger i `docs/runbooks/`.
- Supabase-schemat är förberett för Klass 1-krypterade tabeller (M2), men innehåller inget Klass 1-data ännu.

## Utlämnat från M0 (skjuts till senare milstenar)

- **AWS-relaterat** — Terraform, ECS, RDS, ElastiCache, KMS, Secrets Manager, VPC. Vercel + Supabase ersätter alla.
- **Ory Kratos** — Supabase Auth täcker M0-behovet.
- **NestJS-plattformsarbete** — Next.js Route Handlers är enklare struktur; vi behöver ingen egen DI-behållare eller framework-specifika tester i M0.
- **Klass 1-kryptering med pgsodium** — förbereds i schemat men aktiveras först i M2 (C-03 Cycle & Health), inte i M0.
- **Prisma migrations-pipeline** — förenklad; Prisma migrate mot Supabase direkt, inget separat migration-jobb i M0.
- **OpenTelemetry** — ersätts av Vercel Logs + Axiom + Sentry. OTel kan komma tillbaka i M4 om vi behöver distribuerad tracing.
